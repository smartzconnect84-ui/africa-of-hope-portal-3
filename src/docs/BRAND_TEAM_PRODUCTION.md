# Brand, uploads and Team production checklist

## Implemented
- Owner-supplied official mark is the source in `src/build/brandAssets.ts`. The dev/build scripts prepare static assets before Vite starts, and the Vite production plugin also emits them: same-origin `/logo/aoh-logo.png`, 32px `/favicon.png` and `/favicon.ico`, 180px Apple touch icon, 192px/512px install icons and a separate 512px maskable icon. All keep the entire mark; maskable artwork fits within the safe circle on white. Production builds fail rather than shipping a placeholder if source retrieval fails.
- Production output contains these images; runtime branding does not depend on the chat image host. Use `bun run brand:prepare` to regenerate the static public assets separately. Build infrastructure needs outbound HTTPS to the permanent supplied image URL and the installed `sharp` build dependency. Do not omit development dependencies before building.
- Public, footer, portal, sign-in, certificate and brochure default logos, favicon, launch screen, manifest and offline page use the mark. A one-time brandRevision=2 presentation upgrade applies the requested replacement to older saved settings. Subsequent published CMS overrides stay independent.
- Full-image contain/center display is shared across image uploads, blog covers, homepage, team and CMS previews. Hero fades remain; image zoom/cropping is disabled. Empty margins are intentional when the uploaded proportions differ from the slot.
- Team uses the existing `system_settings.website_settings.team` JSON and `site-assets/team` uploads; no new table, migration, private staff query or backend is introduced. Public profiles are explicitly curated, not generated from staff accounts.

## Publish/setup (authorized administrator)
1. Existing Supabase prerequisites must be applied: system settings with website_settings JSON, roles/CMS RLS, and the public site-assets bucket with administrator write policies. Review the existing versioned roles/storage/hardening migrations in staging; this change applies no SQL and changes no production configuration.
2. Sign in with cms.manage. Open Website CMS → Branding & header. The supplied mark is the default for every location. To copy it into the Supabase logo/favicons folders, use **Copy supplied assets to Supabase**, wait for completion, then **Publish changes**. This also stores the supplied founder portrait in the team folder. Uploading alone is not publishing. Existing objects are retained.
3. Open Website CMS → Team page. Review the seeded founder details and portrait, edit/add/reorder/remove public profiles and set the page visibility. **Publish changes** awaits the existing Supabase settings write and reports failures. The one-time teamRevision=1 seed adds the owner-approved founder to older settings without deleting existing members. Once published, deleting him or disabling the page stays effective.
4. Build and publish the app over HTTPS with the existing Supabase URL/public key environment variables. Vite emits the required brand files into the production output. Do not serve raw source/public alone as the finished app.

## Acceptance checks still requiring a live environment
- As an authorized administrator, publish an edited founder role/photo, refresh in an anonymous tab at `/#team`, and confirm the persisted details. Try a second account without cms.manage; settings writes and storage uploads must be denied. Test failed uploads and failed settings writes without success messages.
- Add/reorder/delete a profile, publish and refresh. Disable the team page and confirm the page shows an unavailable message and home cards disappear. Re-enable it and publish. Private staff profiles must never be listed.
- Upload portrait/landscape/transparent images in Blog, hero, logos, homepage section and team placements; check full content at 320px and desktop widths.
- Check `/favicon.png`, `/logo/aoh-logo.png`, `/icons/icon-192.png`, `/icons/icon-512.png`, `/icons/maskable-512.png` and `/icons/apple-touch-icon.png` return image/png with the declared dimensions from the production host.
- Install on Android and iOS from HTTPS. Confirm home-screen icon, OS launch identity and React launch screen. OS launch screens are platform-managed from the manifest/touch icon and cannot be forced identically by web code. Existing installations may require an OS refresh/reinstall to refresh identity.
- Accept the waiting service-worker update only when ready, test offline relaunch and reconnect, and verify portal/API responses are not cached. Real-device installation and live Supabase publishing are not claimed verified by compilation.
